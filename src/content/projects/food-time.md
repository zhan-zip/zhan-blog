# 项目简介

如您所见，这是一个基于 FastAPI + Vue 3 + DeepSeek/Qwen VL 的智能饮食辅助网站，板块不少，从食物营养数据到分析和生成食谱到记账再到agent均有涉猎。

## 架构简介

**前端**：Vue 3 + Vite + 纯 CSS 桌面端组件 + Pinia + Vue Router

**后端**：FastAPI 异步框架，8 个功能模块，JWT 认证

**数据库**：MySQL 8.0，15 张表，utf8mb4

**用到的ai**：DeepSeek chat 对话与工具调用，Qwen VL 视觉识别

# 功能模块

主要写agent助手模块，其他部分放在下一个部分简单介绍。

## Agent助手-跟前端调用LLM的区别是啥？

本项目的agent本质上是一个 **Tool-Calling Agent**（也叫 ReAct 式 Agent，Reason + Act）。

简单解释一下，它不直接凭LLM模型记忆回答，而是先判断"这个问题要不要查数据、查什么数据"，然后调用工具去数据库/外部 API 拿真实结果，再基于结果组织回答。这样回答有依据，不靠模型编造。

做的是**前置多轮**工具调用，没有做交错式的。也就是说，只有一开始会有三轮调用工具的循环判断，LLM自己判断需不需要其他工具，之后不再调用。虽然没有交错式看起来智能，但一般是够用的。

每个**工具**的耦合性很低，利于拓展，这也是为啥我爽写了12个。**SSE流式**也是不用说了，一般都会做。

对于***防幻觉***和***记忆***的部分后面详细说，这里先看架构。

### 架构

具体架构如下。

```
前端 Assistant.vue（SSE 流式）
  ↓ 用户消息
chat/service.py ChatService.run()        ← 对话管线主入口
  ├─ 构建 5 层 System Prompt
  ├─ 多轮 Tool-Calling 循环（≤3 轮）      ← 判断要不要调工具
  │    ├─ DeepSeek 返回要调工具 → execute_tool() 执行 → 结果回填
  │    └─ 不再调 → 跳出
  ├─ chat_stream 流式输出最终回答
  └─ 保存对话 + 每 6 轮提取长期记忆
chat/tools.py  TOOLS 定义 + execute_tool()  ← 12 个工具的具体实现
services/      deepseek / qwen / vector_store / diet_guideline ...
```

### 五层System Prompt

Layer 1 红线规则（严禁编造数据）

Layer 2 人设（persona.txt，模块级缓存）

Layer 3 长期记忆 + 用户信息

Layer 4 RAG预获取（用户消息→ChromaDB语义检索top3）


Layer 5 工具清单 + 调用规则后面的后面再写
