# 引言

这个机器人最初只接 QQ（NapCat/OneBot），后来把"接消息"这件事做成了可插拔的适配器：同一套核心，现在既能接 QQ，也能在浏览器里打开一个网页界面直接对话，协议层完全可插拔，接入新渠道只需新增一个适配器。

由于 napcat 实际上是违反 qq 使用协议的，怕被制裁，该项目不会公开源码。这里也只是介绍一下。

# 项目简介

一句话：一个全异步 Python 实现的 QQ agent 机器人——它不只是"回消息"，它有记忆、会用工具、会主动发起聊天、会自己发空间动态，还能被其他 AI 程序调用。

## 技术栈与架构

**语言/框架**：Python 全异步（asyncio + aiohttp），单进程并发处理多用户，长耗时操作（搜索/翻空间）不阻塞其他消息。

**接入层（可替换）**：

| 适配器 | 说明 |
| :--- | :--- |
| OneBot v11（NapCat） | QQ 消息收发，主渠道 |
| 自制 Web 适配器 | aiohttp WebSocket + 内置网页，浏览器打开 `127.0.0.1:8080` 就能聊 |

两层共用一套核心处理逻辑，渠道差异全部下沉到适配器，换渠道只写适配器。

**模型层（多套 + 容灾）**：

- **DeepSeek**：主对话模型
- **Qwen（通义千问）**：备用对话模型 + 视觉识别（qwen-vl-max）+ 文本向量（text-embedding-v3）
- 全部走 OpenAI 兼容协议，想换任何兼容服务商，改配置即可，零代码

**数据层**：SQLite（对话历史/长期记忆/事件/待办，FTS5 关键词检索）+ ChromaDB（向量语义检索）+ 沙箱工作目录（文件工具专用）。

**自动化**：Playwright 无头浏览器模拟操作 QQ 空间——发动态、翻动态、看详情，全自动。

**集成**：MCP 协议双向——既是客户端（调用其他 agent 的工具），也是服务端（把自己的能力开放给别人）。

## 核心链路

一条消息进来，走完这趟旅程：

> 接住消息 → 白/黑名单安检 → 提前查资料（搜索/链接/看图/回复引用）→ 判断是不是命令 → AI 决定（要工具就给工具结果，最多三轮）→ 防幻觉检查 → 发回 → 记账

# 功能与技术亮点

## 1. Agent 工具链：15 个内置工具 + 动态并入

AI 自己不动手，它"点菜"声明要用哪个工具，程序真的执行，把真实结果喂回去，AI 再基于结果组织回答——最多循环 3 轮，防止钻进工具里出不来一直烧钱。

内置工具分五类：

| 分类 | 工具 | 说明 |
| :--- | :--- | :--- |
| 基础 | 查时间、联网搜索 | 博查搜索，可配置触发词自动搜索（"今天/最新/天气"等词自动触发） |
| QQ 身份 | QQ号解析、查用户资料、查机器人资料 | 解析按"自己→对话用户→好友→陌生人"四优先级找真实身份，防 AI 编昵称 |
| QQ 空间 | 读动态、发动态 | 读动态分"自己的/好友圈/指定QQ号"三种模式；发动态带进度回调 |
| 文件 | 读/写/追加/列目录 | 沙箱工作目录，路径越界直接拒绝 |
| 待办 | 创建/查询/更新 | 结构化存储（SQLite），重启不丢 |

外加 MCP 并入的外部工具（见第 7 点），工具清单运行时自动合并。

## 2. 多模型路由与容灾

主对话 DeepSeek，挂了自动切 Qwen 备用再试一次；两套都挂还有降级兜底——对话不卡死、主动行为跳过、空回复防呆。视觉、向量各有独立模型位。路由和模型全部走配置，接新模型零代码改动。

## 3. 三层记忆 + 语义检索（RAG）

- **短期**：对话历史进 SQLite，每人最近 20 条，内存缓存 + 异步落盘，重启不丢，`#重置` 可清空
- **长期**：每聊满 6 轮，让 AI 从对话里抽出"关于用户的重要事实"存档案，下次对话拼进指令——再见不是陌生人
- **语义**：ChromaDB 向量库，每轮对话按用户当前的问题做语义检索、注入相关历史（默认 top 5），能接上"上次聊的那只猫"
- **事件记忆**：撤回这类事件只记"发生过"、不记内容——它知道细节才编得出，不知道反而编不了

## 4. 四层防幻觉

AI 是猜字机，所以拦它靠四道程序强制闸门：

1. **开场立规矩**：系统提示词第一段是"最高优先级规则"（压过一切人设），列 12 类禁编字段（昵称/签名/QQ号/空间动态/权限状态/生日/星座/头像……），工具没返回的字段只能说"未设置"或"未知"
2. **敏感词强制查证**：用户话里命中 14 个敏感词（空间/昵称/签名/头像……），强塞"必须调用工具拿真实数据，严禁编造"的系统指令
3. **撤回要真凭实据**：AI 回复出现"撤回"两个字，必须对上"已确认撤回清单"（双重证据确认过），对不上整句替换
4. **动手前先验明正身**：AI 想改资料只能靠暗号，程序先翻用户原话——没有"改/换/设置"这类显式动词，暗号作废不执行

## 5. QQ 空间自动化（Playwright）

无头浏览器 + 登录 cookies，真实操作 QQ 空间：发动态、翻动态列表、看动态详情、好友圈。耗时操作有"进度消息"机制：先安静 5 秒（活儿快就没人察觉），没干完就每 10 秒发一句"正在处理中，请稍候~"，干完自动闭嘴——用户不会以为它卡死了。

## 6. 主动行为（agent 的主动性）

- **主动找人聊天**：每 60 分钟检查一次，好友超过 3 小时没联系、开了开关，就让 AI 评估"现在发消息合不合适"（不合适就跳过），每人每天最多 2 条
- **定时任务**：配置里写"每天早上 8 点给某人发消息"，可开 AI 生成，内容按当时场景现写
- **自主改资料**：每 60 分钟让 AI 决定要不要换昵称/签名（6 小时冷却，避免频繁变动）
- **自主发空间动态**：每 90 分钟评估要不要发条说说（3 小时冷却）
- 凡是动真格的（改资料、发动态），都给管理员发一条通知留底——自作主张可以，但管理者得知道它干了啥

## 7. MCP 双向集成

- **作为客户端**：启动另一个项目（Food-Time）的 MCP server 子进程，自动拉取它的工具清单并入自己的工具集——两个项目零手写对接，AI 对话中直接能用"饮食记录/营养查询"这类外部工具
- **作为服务端**：向其他 agent 暴露自己的能力：发消息通知、查运行状态、查机器人资料、读待办

## 8. 撤回检测（三重路径）

通知事件主路径 + 消息反查兜底 + 后台每 30 秒扫描最近 5 分钟的消息。"服务器查无此条 + 本地存过原文"双重证据齐了才认定为真撤回，撤回编号进白名单——AI 再爱脑补"用户刚才撤回了啥"，也被拦得死死的。

## 9. 稳定性设计（无人值守）

- **断线自动重连**：2 秒 → 4 秒 → 8 秒……指数退避，上限 60 秒，连上为止；重连后清掉依赖旧连接的临时状态
- **外部服务失败只影响一步**：搜索/网页抓取失败静默跳过（当没查过）；图片下载/识别失败明确告诉 AI"不要假装看到"
- **模型全挂有兜底**：对话不卡死、主动行为跳过、绝不给用户发空消息
- **后台循环全部异常隔离**：单个任务出错不拖垮整个程序
- **11 套 mock 测试**：路由容灾 / 记忆 / 向量检索 / MCP 端到端 / 资料修改护栏 / 协议 mock / 核心回归等

## 10. 指令系统与群聊

`#搜索` / `#qzone` / `#动态列表` / `#发动态` / `#修改昵称` `#修改签名` `#修改头像` `#修改背景` / `#查看资料` / `#重置`（清记忆）/ `#history`（回看最近对话）等。资料修改还支持自然语言："改名为XX"会被意图识别当场解析执行，且带二次护栏（解析出的"新名字"像疑问句就拒绝，防止"叫什么"这类提问被误判成改名）。群聊可配置只回应 @ 自己的消息，自带 3 秒消息冷却防刷屏，支持白名单/黑名单。
